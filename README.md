# JobDesk 0.3 — локальный поиск работы

## Компания и срок Telegram-постов

Компания автоматически определяется из явной строки «Компания: …» или заголовка вроде «Тестировщик ПО QA Junior в GedoTab». В подборке из нескольких компаний используется выбранный заголовок, а не первая компания в общем тексте. Работодатель подставляется в ручную форму без перезаписи пользовательского ввода; перед поиском исправляется пустое поле уже сохранённой карточки, если компания определяется однозначно.

Поиск контактов в Telegram ограничен последними **тремя календарными месяцами** с начала граничного дня по локальному времени. Более старые и бездатные посты не используются. На границе месяца учитываются 28/29/30/31 дней. Проверка даты действует также для Telegram-постов, найденных через веб, и сохранённых ранее доказательств: старый контакт не возвращается из кеша при ошибке повторного поиска. Выбранные пользователем контакты не удаляются автоматически. Usernames каналов-источников не считаются прямыми контактами рекрутера.

Для Google-выдачи нужен ключ Serper, если Google возвращает JavaScript-заглушку или CAPTCHA. Ключ вводится локально в настройках, ссылка на получение ключа находится там же. Пока ключа нет и Google недоступен, приложение продолжает Telegram-поиск и проверку известных карьерных ссылок, а веб-этап честно отмечается неполным.

## Карьерная страница и форма отклика

Если после веб-поиска и проверки постов Telegram нет прямого контакта, приложение ищет карьерную страницу и читает ссылки из исходной вакансии. Обход ограничен восемью страницами, четырьмя переходами и бюджетом времени; читаются только публичные страницы с учётом robots.txt.

Для подтверждённого маршрута проверяются совпадение компании и названия вакансии, связь сайта с работодателем и наличие формы отклика либо email для резюме. Проверяется исходный сайт компании и переход на ATS из его вакансии; поддерживается чтение встроенных форм и одна попытка отрисовки JavaScript-формы. Поисковый результат, неизвестный сайт, форма входа, поисковая строка и подписка не подтверждают способ отклика. Другой уровень/роль, закрытые вакансии и офисный/гибридный формат отбрасываются.

В карточку сохраняется ссылка на страницу формы (при наличии — с якорем), а не на POST-адрес её отправки. Email извлекается из описания нужной вакансии и явно обозначенных ссылок для отклика, в том числе за пределами JSON-LD. Переходы и результаты проверки записываются в журнал. Непроверенные варианты помечаются кандидатами; подтверждённый маршрут ставится перед исходным job board, неподтверждённые варианты — после него. Ничего в формах не заполняется и не отправляется автоматически.

Порядок: прямой Telegram/email → подтверждённая форма или email на странице вакансии компании → исходная ссылка HH/job board. При недоступном поисковике проверяются уже известные ссылки; неполный поиск обозначается в журнале. Совпадение проверяется правилами по названию и компании, без семантической модели: существенно изменённый заголовок может остаться неподтверждённым.

## Ручная карточка и поиск контактов

После вставки текста вакансии «Должность» подставляется из заголовка / строки «Вакансия: …». Ручное исправление не перезаписывается последующими изменениями описания. При импорте страницы используется извлечённое название вакансии.

Поиск контакта проверяет исходное описание, запрос по вакансии, отдельный запрос по компании + HR / рекрутер / Telegram и, при необходимости, карьерную страницу. HR-профиль компании может быть релевантен без названия должности. Учитываются варианты написания названия компании с точками и пробелами, абсолютные Google redirect-ссылки и превью результата поиска. Контакт из превью остаётся неподтверждённым кандидатом.

**Telegram проверяется независимо от результата веб-поиска.** По всем Telegram-источникам (включая отключённые для сбора) ищутся посты по отличительной части названия компании, затем проверяется совпадение компании в тексте. Читается до 10 найденных постов на канал только за последние три календарных месяца, проверяются текст, скрытые ссылки и URL-кнопки. Посты не обрезаются до 10 на весь аккаунт. Сохраняются найденные контакты и все ссылки-доказательства; повторные упоминания объединяются. Ошибки, FloodWait и частичный обход видны в журнале, уже найденные посты не теряются при достижении лимита времени.

Пример живой проверки: для Middle QA Engineer в Plat4m.Tech контакт найден в двух постах taksa_offer от 29 октября 2026 года. Ранее контакт терялся, поскольку находился в скрытой Telegram-ссылке.

Google может отдавать заглушку JavaScript / CAPTCHA. В этом случае веб-поиск помечается недоступным и продолжается Telegram-поиск. Для устойчивой Google-выдачи нужен собственный ключ Serper; отсутствие контакта нельзя гарантировать при недоступности части источников. Контакты не выбираются автоматически. Результаты обновляются прямо в открытой карточке без потери несохранённого письма.

Изменения в этом разделе имеют приоритет над описанием алгоритма 0.2 ниже.

## Формат работы и подключение HH

При включённом «Только удалённая работа» упоминания офисного и гибридного формата исключают вакансию, даже при наличии альтернативы «удалённо». Проверяются русские варианты и office / on-site / hybrid; упоминание программ Microsoft Office само по себе не считается офисным форматом.

Для OAuth-доступа HH зарегистрируйте приложение на https://dev.hh.ru/ и получите Client ID / Client Secret. Затем локально выполните:

```bash
cd /Users/redcollar/Desktop/jobdesk
.venv/bin/python scripts/connect_hh.py
```

Скрипт скрыто запрашивает Client Secret, получает токен приложения через официальный endpoint, сохраняет только токен в локальном `data/search.json` и проверяет доступ к поиску. Client Secret не сохраняется и не выводится. При уже сохранённом токене выполняется только диагностика. Email в User-Agent не заменяет OAuth-доступ; HH может ограничить доступ и для авторизованного приложения.

## Сортировка и период сбора

На доске (внутри каждого этапа) и в таблице карточки упорядочены по дате публикации от новых к старым. Карточки без даты находятся в конце истории; дата добавления не используется вместо даты публикации.

Рядом с «Собрать вакансии» выбирается период: 1 день (24 часа), 1 неделя (7 суток), 2 недели (14 суток), 3 недели (21 сутки) или месяц (один календарный месяц с начала дня). Выбор запоминается для общего, отдельного и автоматического сбора. Начало периода фиксируется один раз на весь запуск; HH, Telegram и общий фильтр всех источников используют одну границу. Выбор периода сразу фильтрует уже сохранённые карточки на доске и в таблице откликов, а также счётчики и воронку. Это действует для всех режимов отбора, включая «Все этапы за период». За пределами периода, в будущем и без даты публикации карточки не показываются; сохранённые данные не удаляются. Повторный сбор для применения фильтра не нужен.

Telegram-каналы из папки аккаунта можно импортировать повторно без дублей:

```bash
.venv/bin/python scripts/import_telegram_folder.py вакансии
```

Поддерживаются публичные и закрытые каналы, к которым уже есть доступ у подключённого аккаунта. CSV сохраняется локально в `data/telegram_vacancies_sources.csv`. Личные чаты не импортируются; Telegram-сессия, ключи и CSV исключены из Git.

## Исправления сбора и отклика в 0.3

- Исправлены штатные адреса Talent Move и HireHi: сбор больше не использует запрещённую robots.txt поисковую страницу Talent Move. Старые штатные адреса обновляются автоматически; пользовательские источники и фильтры сохраняются.
- HTML-сбор проходит страницы ленты, включая кнопочную пагинацию Talent Move. Лимит за запуск — 20 страниц / 400 карточек; ошибки и неполный обход показываются в статусе источника.
- Активная доска показывает только публикации за один календарный месяц. Старые и бездатные карточки доступны через «Вся история». При сборе старые, будущие, бездатные и исключённые сохранёнными фильтрами вакансии пропускаются.
- Для Talent Move читается полный текст вакансии, а не краткое SEO-описание. Русские заголовки разделов HireHi больше не превращают английское описание в русскоязычное.
- Дубли определяются по каноническому URL (включая региональные домены HH), а между сайтами — по компании, названию, близким датам и сильному сходству текста. Совпадение компании и должности без сходства текста недостаточно. Сохраняются этап, письмо, заметки и ссылки всех источников. Ранее сохранённая дата не заменяется новой датой повторного обнаружения. Неодинаковые пересказы одной вакансии могут потребовать ручной проверки.
- Автоматический поиск контактов включается при обновлении на 0.3; его можно выключить в настройках. Сначала собираются все источники, затем обрабатываются подходящие свежие карточки, для которых поиск ещё не выполнялся. Проверяются контакты в тексте, Google (до трёх релевантных страниц), дополнительный запрос для карьерной страницы и Telegram при отсутствии контакта. Ошибка поиска контакта не останавливает сбор.
- В карточке и на доске показываются варианты отклика: прямой контакт, карьерная страница, исходный job board. Карьерные страницы из поиска помечаются кандидатами: совпадение вакансии и работодателя нужно проверить. Письма сами не отправляются.
- В настройках HH можно сохранить OAuth access token зарегистрированного приложения. Email в User-Agent не даёт права доступа. Токен хранится в `data/search.json` с правами 0600, не возвращается через API и не попадает в экспорт. Наличие токена не гарантирует доступ при ограничениях HH; 403 содержит реальную ошибку и request_id. Другие источники продолжают работать.

После обновления перезапустите `bash start.command` и нажмите «Собрать вакансии». Не заменяйте свою папку `data`. Для автоматического повторения раз в сутки включите соответствующую настройку: приложение должно оставаться запущенным.

Ограничения: месяц проверяется по дате, предоставленной источником; переопубликованная старая вакансия может иметь новую дату у агрегатора. Google может требовать CAPTCHA — для устойчивого поиска предусмотрен собственный ключ Serper. Jobtoo и Dream Offer могут не отдавать карточки из-за ошибок сайта, согласий или защиты; это отображается как ошибка источника, а не отсутствие вакансий. Ограничения и закрытые контакты не обходятся.

Ниже сохранены инструкции предыдущей версии; изменения выше имеют приоритет.

Вакансии, канбан, таблица откликов, события, CV, источники, поиск контактов и Telegram. Для одного пользователя, без обязательного AI, Node.js и Docker. Открывается по http://localhost:8765 .

## Обновление с 0.1 — сохранить свои данные

1. Остановите старое приложение: Ctrl+C в его терминале.
2. Сделайте резервную копию **всей старой папки `data`**. Там база, PDF, настройки и Telegram-сессия.
3. Распакуйте новый архив в отдельную папку.
4. Замените папку `data` в новом проекте вашей старой папкой `data` целиком.
5. В новой папке выполните:

```bash
bash setup.command
bash start.command
```

При запуске база обновится автоматически. Карточки, письма, этапы, заметки и сессия сохранятся. Не заменяйте свою папку `data` пустой папкой из архива. Старые карточки без сохранённой даты публикации получат пометку «Дата не подтверждена», а не выдуманную дату. После нового сбора совпавшие вакансии смогут получить дату из источника.

## Первый запуск на Mac M4

Нужен Python 3.10+. Проверка: `python3 --version`. При отсутствии установите стабильную universal2-версию с https://www.python.org/downloads/macos/ .

Откройте Терминал, напишите `cd ` с пробелом, перетащите папку `jobdesk` в окно терминала и нажмите Enter.

```bash
bash setup.command
bash start.command
```

Откройте http://localhost:8765 . Для остановки Ctrl+C. Для повторного запуска достаточно `bash start.command`.

Если после установки Python с python.org возникают ошибки TLS-сертификата, выполните `Install Certificates.command` из папки Python в «Программах». Проверка сертификатов в приложении не отключается.

## Новое в 0.2

### 1. Публикация не раньше месяца назад

Порог рассчитывается **в момент сбора**: текущая локальная дата минус один календарный месяц, с начала дня. Например, 1 ноября → 1 октября включительно; 31 марта → последний день февраля. Это не фиксированные 30 дней. Время учитывается в часовом поясе устройства.

- HH получает `date_from` и `date_to`, затем дата проверяется повторно.
- Telegram: используется дата сообщения; просмотр до 2000 сообщений, прекращается при достижении порога.
- RSS/Atom: `pubDate` / `published`.
- JSON-LD: `JobPosting.datePosted`.
- HTML: метаданные публикации, `time[datetime]`; Talent Move — также «Опубликовано: ДД.ММ.ГГГГ», HireHi — дата в заголовке страницы.
- Без подтверждённой даты автоматический сбор **не создаёт новую карточку**. В статусе источника есть отдельный счётчик «без даты».
- Будущие даты и старые публикации тоже считаются отдельно и пропускаются.
- Ручная карточка может быть сохранена без даты с пометкой для уточнения. Дату можно указать/исправить в форме.
- На уже сохранённых карточках свежесть пересчитывается при чтении: со временем старая публикация перестанет попадать в активную подборку. История откликов не удаляется.

Дату первого обнаружения приложение не выдаёт за дату публикации. Переопубликованное объявление оценивается по дате, предоставленной источником: определить, что это старая вакансия под новой публикацией, без дополнительных данных невозможно.

### 2. Контакт HR на каждой карточке

На доске и в таблице отображается выбранный контакт либо статус: «ещё не искали», «найдены кандидаты», «не найден», «поиск неполный», «ошибка». Везде есть кнопка «Найти контакт»; внутри карточки — кандидаты с контекстом, ссылкой на источник и журналом.

Алгоритм:

1. Запрос Google: `вакансия <название> <компания>`.
2. Среди результатов выбираются первые **три релевантные** ссылки по совпадению компании и ключевых слов должности. Релевантность определяется простыми правилами, без AI.
3. Открываются страницы; извлекаются email, `mailto:`, `t.me`, `telegram.me`, `@username` из видимого текста и контактных ссылок. Явные Telegram-боты исключаются.
4. Если веб-страницы не дали контактов, выполняется поиск названия компании в Telegram-каналах из списка источников (включая временно отключённые для сбора).
5. Из каждого канала запрашиваются до десяти найденных постов, объединяются по дате; проверяются **первые десять постов суммарно** по всем каналам. Для поиска контакта нет ограничения по месяцу, поэтому старый контакт нужно перепроверить.
6. При отсутствии результата после успешного полного прохода — «Контакт не найден». При CAPTCHA, отсутствии каналов/сессии, сетевой ошибке — «Поиск неполный», а не ложное «ничего нет».

Контакт из страницы может оказаться поддержкой, каналом или другим сотрудником. Приложение сохраняет **кандидатов**, не считает каждый `@` подтверждённым HR. Нажмите «Выбрать этот контакт» после проверки источника. Поле отправки само не заменяется. Email тоже можно сохранить, но отправка email в этой версии отсутствует. Telegram-отправка принимает только личный Telegram-аккаунт.

**Google:** без ключа приложение пробует обычную HTML-выдачу. Google может вернуть CAPTCHA, согласие или неудобную для разбора страницу. Обхода защиты нет. Для более стабильного получения Google-выдачи можно подключить сторонний API Serper: https://serper.dev/ → собственный ключ → «Настройки поиска → Google-поиск контактов». У сервиса свои условия/лимиты. Передаются только название компании и вакансии; CV не передаётся. Ключ хранится локально в `data/search.json` с ограничением прав, не возвращается через API и не попадает в экспорт. При сбое Google приложение всё равно попробует Telegram.

Кнопка поиска работает в фоне. Когда поиск завершится, закройте и заново откройте карточку, чтобы увидеть результаты; несохранённый текст формы не перезаписывается автоматически.

В настройках можно включить поиск контактов для новых карточек автосбора. По умолчанию выключен: Google-запросы могут иметь лимиты, а проверка всех карточек занимает время. Для вручную добавленной карточки используйте кнопку.

### 3. HeadHunter: поиск без откликов

В 0.1 запросы не имели контактного email в идентификаторе приложения, не передавали период публикации, не показывали ответ HH достаточно подробно и отключали системные HTTP-прокси.

В 0.2:

- `HH-User-Agent: JobDesk/0.2 (<контактный email>)`;
- настройки email проверяются до запроса;
- публичный GET-поиск и получение описаний, без отправки откликов;
- период публикации задаётся в запросе;
- при ошибке показываются HTTP-код, сведения из `errors`, `request_id` и подсказка;
- распознаются ошибки сети и TLS, используются настроенные системные прокси;
- есть кнопка **«Проверить доступ к HH API»**.

Что нужно от вас:

1. «Настройки поиска» → укажите контактный email в поле HH → «Сохранить настройки». Это обратная связь для идентификации личного приложения, не подключение ящика.
2. Нажмите «Проверить доступ к HH API».
3. При `ok: true` запустите сбор HH. При ошибке скопируйте показанный JSON для диагностики.

Логин, пароль, резюме и авторизация соискателя для реализованного публичного поиска не используются. Код не делает запросов отправки откликов. Если HH ответит 401/403, решение зависит от реального ответа: ограничение IP, CAPTCHA, политика API или необходимость регистрации приложения; не подставляйте пароль аккаунта в настройки.

Приложение делает до двух страниц по 30 результатов на поисковую фразу и сохраняет до 60 уникальных подходящих по названию объявлений за запуск. Это ограниченный сбор, не полный обход всех результатов за месяц. Фразы задаются в настройках приложения; параметры URL источника HH не подменяют их.

| Источник | Причина проблемы в 0.1 | Изменение / текущая граница |

Установка браузерного модуля (один раз в папке проекта):

```bash
bash setup_browser.command
```

Устанавливаются Playwright и Chromium. При работе сначала пробуем установленный Google Chrome, затем Chromium. Перезапустите JobDesk. В источнике можно выбрать тип «Браузер (JavaScript)» и уточнить шаблон ссылок. Сбор ограничен текущей страницей, тремя прокрутками, до 25 переходами к карточкам. Сайты с иной схемой дат или данных могут не распознаться.

Нет обхода CAPTCHA, оплаты, авторизации и закрытых разделов сайтов. Если сайт требует согласия/логина или запрещает чтение, используйте ручной импорт. Сбой браузерного модуля показывается как ошибка источника, а не как доказательство отсутствия вакансий. Источники доступны для добавления/редактирования/отключения/удаления через интерфейс.

**Живой сбор на вашем устройстве ещё необходимо проверить.** Сетевые ограничения среды разработки не позволяют подтвердить ответы всех сайтов и Telegram-аккаунта. Исправление известной ошибки парсера не является доказательством работоспособности любого сайта целиком.

## Telegram: подключение и отправка

Остановите сервер Ctrl+C. Получите собственные `api_id` и `api_hash` на https://my.telegram.org → API development tools.

```bash
.venv/bin/python scripts/connect_telegram.py
```

Введите API ID/hash, телефон, код, пароль 2FA при необходимости. Секреты вводятся локально, сообщения при подключении не отправляются. Затем `bash start.command`. В источниках добавьте `@channel` или `https://t.me/channel`. Закрытые invite-ссылки пока не поддерживаются.

В карточке укажите проверенный Telegram-контакт и источник, сохраните письмо, откройте предпросмотр, проверьте текст/PDF, отметьте подтверждение. Только после этого нажмите отправку. Письмо с PDF — одним сообщением, до 1024 знаков. Одноразовое серверное подтверждение на 10 минут связано с письмом, адресатом, карточкой и хешем PDF. Изменения требуют нового предпросмотра.

При неопределённом результате повтор блокируется: сообщение могло уйти. Проверьте диалог вручную. Follow-up через приложение пока отсутствует. «Проверить ответы» получает текстовые сообщения из диалога после отправки; у рекрутера может быть несколько вакансий, поэтому проверяйте связь сообщения с карточкой. Этап автоматически не меняется.

Для отключения на остановленном сервере удалите `data/telegram.json` и `data/telegram.session*`, при необходимости отзовите сеанс в Telegram → Устройства.

## Данные и ограничения

- Канбан, таблица, письма, история, события и настройки хранятся в SQLite.
- Поиск по названиям: хотя бы одно включение, отсутствие любого исключения, границы слов; технологии в описании не исключают вакансию.
- География/язык определяются эвристиками. Неоднозначные случаи требуют проверки; работа «по Европе» не означает автоматически работу из Грузии.
- JSON/CSV — текстовый экспорт; полный бэкап — вся `data` при остановленном сервере. JSON-импорт отсутствует.
- PDF загружается до 15 МБ, текст извлекается без OCR. Правки текста профиля не меняют вложенный PDF.
- В архив включены ваше CV и текст профиля. Не передавайте архив другим без удаления `seed_profile.txt` и `data/base_cv.pdf`.
- `data/telegram.session`, `telegram.json`, `search.json` приватны. Приложение не шифрует данные само; используйте защищённую учётную запись macOS / FileVault.
- Сервер слушает только 127.0.0.1. Не публикуйте через туннель: авторизации для размещения в интернете нет.
- AI, MCP, управление из этого чата, Mail.ru/Gmail/WhatsApp, отправка через HH, автоматическое заполнение форм, внешние календари и системные напоминания не включены.
- Календарь — список событий; событие можно удалить и создать заново. Воронка — текущее распределение этапов, не историческая конверсия.
